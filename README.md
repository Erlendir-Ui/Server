# Server

Personal, provider-agnostic server infrastructure.

## Цель

Личный сервер для безопасного удалённого доступа и размещения сервисов.

Главный принцип — быстрое и воспроизводимое развёртывание на новом VPS независимо от провайдера.

## Архитектура

Base system → SSH → Firewall → Docker → Fail2Ban → Monitoring → Backup → VPN

VPN остаётся отдельным модулем, чтобы базовую систему можно было переносить между VPS без привязки к конкретному протоколу.

## Быстрый запуск

\`\`\`bash
git clone https://github.com/Erlendir-Ui/Server.git
cd Server
sudo ./install.sh
\`\`\`

Перед запуском на удалённом сервере убедитесь, что у вас есть рабочий способ повторного подключения по SSH.

## Безопасность

1. Секреты не хранятся в Git.
2. По умолчанию открыт только необходимый SSH-порт.
3. VPN-порты открываются отдельным этапом.
4. Password authentication не отключается автоматически до подтверждения доступа по ключу.
5. Docker и VPN настраиваются отдельно от базовой системы.
6. Конфигурация должна быть воспроизводимой и пригодной для быстрого переноса на новый VPS.

## Примечание по Docker и firewall

Docker публикует контейнерные порты через собственные сетевые правила. Поэтому перед публикацией VPN-сервисов будет отдельно проверена модель firewall, чтобы случайно не получить открытые наружу порты.


## Тестовый VPS

Для первого запуска рекомендуется чистый Ubuntu/Debian VPS. Установщик устанавливает базовые системные компоненты, Docker, Fail2Ban, локальный monitoring и backup. Удалённый backup в Google Drive устанавливается как подготовительный модуль, но не активирует timer до отдельной настройки Google OAuth и restic.

Для небольших VPS рекомендуется иметь не менее 1 GB RAM и запас диска не менее 10 GB после установки ОС.
